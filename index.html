LAB 01 · LINE DRAWING

DDA Digital Differential Analyzer — the float-stepping line rasterizer

// HOW IT WORKS

The friendliest line algorithm: measure Δx and Δy, walk the dominant axis in unit steps, and let floating-point increments decide where each pixel lands. Every iteration plots round(x), round(y) as a GL_POINT, so the plotted points hug the ideal line as closely as the grid allows.

steps = max(|Δx|, |Δy|) x_inc = Δx / steps y_inc = Δy / steps plot( round(x), round(y) ) // each step x += x_inc; y += y_inc;
  • One iteration per pixel — the loop runs O(length) times
  • Float error accumulates; long steep lines can wobble
  • Signed increments (x2−x1)/steps make it work in every direction
  • A triangle is just three DDA calls inside one display()

LAB 02 · LINE DRAWING

Bresenham Integer-only line drawing with a single decision parameter

// HOW IT WORKS

One question per column: is the true line closer to the pixel beside us, or the pixel diagonally above? Start with p₀ = 2Δy − Δx. If p < 0 move east and add 2Δy; otherwise step diagonally and add 2Δy − 2Δx. No floats, no rounding — just additions.

The general version picks the driving axis by comparing dx and dy, and walks backwards with ±1 sign steps when endpoints are swapped — so it draws in all four quadrants.

p₀ = 2Δy − Δx p < 0 → x++ p += 2Δy p ≥ 0 → x++, y++ p += 2Δy − 2Δx // dx < dy ? drive y instead, swap roles
  • Pure integer math → faster than DDA on old hardware
  • The error term is exact — pixels never drift
  • dx > dy branch drives x; the else branch drives y
  • The combined demo draws DDA (green) + Bresenham (white) side by side

LAB 03 · CIRCLE & ELLIPSE

Midpoint Circles and ellipses without a single trig call

// HOW IT WORKS

Test which side of the curve a midpoint falls on, step east or south-east, and mirror every computed point into 8 symmetric pixels (4 for the ellipse). Start at (0, r) with p = 1 − r; while x < y: step x++, and if p ≥ 0 also drop y.

circle : p₀ = 1 − r p < 0 → E : p += 2x + 1 p ≥ 0 → SE : y-- , p += 2x − 2y + 1 plot8 → (±x,±y) and (±y,±x) around (xc,yc) ellipse: two regions, switch when 2·ry²·x ≥ 2·rx²·y
  • 8-way symmetry: one eighth of the math draws the full circle
  • The ellipse splits into two regions with different driving axes
  • plot8() / plot4() helpers keep the loop body tiny
  • Try it live in the playground — switch to MIDPOINT ○ and drag B to change r

LAB 04 · 2D TRANSFORMATION

Transform Translation · Rotation · Scaling on the matrix stack

// HOW IT WORKS

Every vertex is multiplied by M = T · R · S. Order matters: glTranslatef → glRotatef → glScalef means the geometry is scaled first, then spun, then moved — so a scaled triangle still orbits the origin the same way.

[ x' ] [ s·cosθ −s·sinθ tx ] [ x ] [ y' ] = [ s·sinθ s·cosθ ty ] [ y ] [ 1 ] [ 0 0 1 ] [ 1 ]
  • In the .c file: WASD translates · R/E rotates · Q/Z scales · 0 resets
  • glPushMatrix / glPopMatrix isolate the transform from the ghost copy
  • Change the call order and the orbit changes completely

LAB 05 · ANIMATION

Animation Timers, idle callbacks and keyboard control in GLUT

// HOW IT WORKS

GLUT has no game loop of its own — you register a timer callback that nudges state, calls glutPostRedisplay(), and re-arms itself every 100 ms. The square below runs the exact same math as animation_timer.c — click it to pause.

void myTimer(int val){ update(); /* change state */ glutTimerFunc(100, myTimer, 0); /* re-arm */ } if (p >= 6 || p <= -10) speed = -speed; /* bounce */
  • glutTimerFunc(ms, fn, val) fires once — always re-arm inside
  • glutSpecialFunc handles arrow keys; glutKeyboardFunc handles chars
  • glutIdleFunc(fn) spins the square every frame — 'k' sets it to NULL and stops it

LAB 06 · SHAPES & 3D

Shapes & 3D From GL_POLYGON soup to a walkable first-person room

// HOW IT WORKS

Everything above draws points and lines; real scenes are built from polygons. GL_POLYGON fills, GL_LINE_LOOP outlines, GL_POINTS sprites — and in 3D, quads become walls, a scaled glutSolidCube becomes a table, and gluLookAt becomes your eyes.

glBegin(GL_POLYGON / GL_QUADS / GL_LINE_LOOP) glVertex2f · glVertex3f · glColor3f glutSolidCube(1) // after glScalef → any box gluPerspective(45, ratio, 0.1, 100) gluLookAt(eye, center, up) // first-person camera glEnable(GL_DEPTH_TEST) // correct occlusion
  • VR room controls: W/S walk forward/back · A/D turn · ESC quit
  • Depth testing needs GLUT_DEPTH in the display mode + glClear of GL_DEPTH_BUFFER_BIT
  • Each table leg = pushMatrix → translate → scale → solidCube → popMatrix
  • The camera moves along its look vector (lx, lz) — pure vector math
TOOLCHAIN · WINDOWS

Setup Compile exactly like we did in the lab — MSYS2 + MinGW64 + freeglut

MSYS2 / MINGW64 — LAB TOOLCHAIN
  1. 1

    Install MSYS2

    Download the installer from msys2.org and open the MSYS2 MINGW64 terminal.

  2. 2

    Install the compiler and freeglut

    Run both packages inside the MSYS2 terminal:

    $pacman -S mingw-w64-x86_64-gcc
    $pacman -S mingw-w64-x86_64-freeglut
  3. 3

    Add MinGW to Windows PATH

    System → Environment Variables → Path → New:

    ▸C:\msys64\mingw64\bin
  4. 4

    Verify the toolchain

    Both commands should respond — the second must list the freeglut libraries:

    $gcc --version
    $ls /mingw64/lib | grep glut
  5. 5

    Compile & run any lab program

    Link freeglut + the Windows OpenGL libraries, then launch:

    $gcc main.c -o app -lfreeglut -lopengl32 -lglu32
    $./app
    ⚠ Link order matters: -lfreeglut -lopengl32 -lglu32. If you get "undefined reference to __imp_...", a library is missing from the command.
